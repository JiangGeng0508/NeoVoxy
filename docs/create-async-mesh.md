# Create 异步网格

本轮实现 roadmap 第三批的 Create 捕获、简化与上传拆分，接入列车车体、转向架、动力机械区段和普通移动结构。既有 LoD 简化算法、距离和默认画质不变。轨道曲线等其他专属模型仍使用同步接口；区段快照、secondary LRU 和其他结果队列的字节背压留在第三批后续。

## 线程与所有权

`CreateMeshService` 为当前客户端实例建立一个 `CreateMeshQueue`，复用 `ServiceManager` 的权重 1 消费者，同一时刻只有一个简化任务。网络形状处理和 tick 只登记捕获配方，Minecraft 模型回调在 `RenderFrameEvent.Pre` 的共享队列中执行。动力机械原有方块实体状态冻结、卸载捕获仍属于 tick／卸载时的来源维护，不计入这条网格捕获预算。

`DistantMeshBuilder.capture()` 移交独占原生顶点缓冲，后台 `CpuMesh.prepare()` 完成半透明合并及既有 LoD 简化，不调用 Minecraft 模型或 OpenGL。既有 `assemble()`／`build()`／`upload()` 保持同步语义。后台结果交回主线程，GPU 缓冲完整上传后才创建 VAO 并发布。`queue/Create mesh` 和 `work/Create simplify` 分别记录请求等待与简化时间。

同一 key 的新请求取消旧版本。等待中的 CPU 结果立即释放；运行中的旧版本由工作线程完成后释放；部分上传的 GPU 缓冲在主线程删除。重建期间保留旧网格，发布新网格后才释放旧网格。失败不发布替代结果。实例关闭和资源重载取消队列并等待运行任务退出，防止旧结果重新安装。

列车车体和转向架全部就绪后才交接给远景；Flywheel 工作线程只读已发布的就绪状态，不登记任务。动力机械用并发集合记录已发布网格实际包含的位置，首次远景网格尚未发布时保留 live 路径。资源重载清理旧网格，列车保留网络来源用于重建，移动结构保留来源，动力机械重新收集。已卸载的动力机械来源会随清理丢弃，需重新加载该区域后恢复。

## 预算与诊断

| 项目 | 口径 |
|---|---|
| 待处理 CPU | 32 MiB，最多 1024 个最新任务，另可有一个取消后仍运行的旧任务 |
| 预留 | 原生顶点容量 × 2；一份顶点容量覆盖保留的粗级数组上界 |
| 主线程工作 | 每帧 2 ms，在完整捕获或上传分块之后检查 |
| 上传 | 每帧合计 2 MiB，每次最多 64 KiB，包含顶点、粗级数据与私有索引 |
| 简化 | 单个后台消费者，权重 1 |

预算在分配／扩容前预留；捕获因容量不足中止时释放部分缓冲并保留配方，只有可用空间达到已知需求才重试。模型内部吞掉容量异常也不能发布截断几何。

**单个模型的原生容量超过 16 MiB 时，双倍预留无法装入 32 MiB 队列。** 当前保留旧网格或仍可用的 live 路径，记录一次警告和 `oversized` 计数，等待来源更新／资源重载，不逐帧重新捕获。尚未实现超大单形状的分块捕获；没有旧网格且已离开实体跟踪范围时，该形状无法生成远景。这是当前明确的容量限制。

32 MiB 是保留的顶点／粗级数组预留，不含列车载荷、捕获配方引用、来源 ModelData／NBT、Java 对象头、简化临时数组、realloc 瞬态内存或 GPU 数据。后续来源与其他队列的字节背压仍需实现。2 ms 不是单帧硬上限：一次 Minecraft 模型捕获或 GL 分配不可在内部中断，可能超过预算。

已有共享 quad 索引足够大时继续复用；不足时，异步上传使用独立索引缓冲，避免分批覆盖可见模型的共享索引。独立索引增加每 quad 24 字节 GPU 存储，计入 `gpuByteSize()`，并随网格释放。移动结构的休眠重建登记还计入其他待重建结构的已知 GPU 大小，避免反复使用尚未兑现的预算空间；原有驻留预算仍在 tick 中执行。

`/voxy debug trains` 和 Create 内存报告显示任务、超限任务、原生缓冲、粗级堆数组、预留／峰值、捕获／简化／发布、过期／拒绝／失败计数及当前／峰值帧工作。粗级堆数组在后台简化完成时计入；进行中的分配由保守预留覆盖。

## 验证

CPU 回归覆盖线程归属、独占缓冲、相同 key 替换、运行中取消、容量释放后重试、吞异常不发布半成品、超限任务停止反复捕获、共享时间／字节预算、部分上传取消、关闭等待、取消回调异常与简化失败清理。

真实 GPU 回归覆盖大于 4 MiB 的替换跨帧上传、旧缓冲保留、原始顶点和粗级数组逐字节一致、私有索引内容／VAO 绑定／GPU 字节计费，以及取消时删除未发布缓冲。首次 GPU 定向运行有 5 项失败：新增夹具未采用顶点编码后的光照值，且新测试套件未清空静态共享索引句柄，影响后续上下文。修正测试后 11 项定向回归全部通过，首次失败证据保留。

```powershell
.\gradlew.bat build --offline --console=plain
.\gradlew.bat build --offline --console=plain -PverifyGpu=true
.\gradlew.bat runClient --offline --console=plain -I scripts/benchmark-model-lod.gradle -PbenchmarkWorld="D:/path/to/world"
# 下一次运行增加 -PbenchmarkShaders=true；分别保存标准 Sodium 和 Iris 日志
python scripts/model-lod-benchmark/summarize.py
```

模型基准在真实 Create 资产上先验证异步捕获／简化／上传，再运行原有 512 实例、1920×1080 的完整模型／LoD 对照。每条渲染管线保留 480 帧和 160 项准备耗时样本。该对照验证当前二进制的模型提交策略，不能解释为异步改造相对历史版本的 FPS 提升，也不替代完整列车运行、资源热重载、Iris／Vista／SeedGen 场景验收。

## 2026-11-01 模型基准

Sodium 与 Iris 两个最终运行通过汇总校验，共 960 个帧样本、320 项准备耗时样本，真实使用 RTX 4060 Laptop／OpenGL 4.6、Create 6.0.10，Iris 使用 Complementary Reimagined r5.8.1。两边各完成 4 个后台准备及发布，队列最终为零，无拒绝、失败或超限任务；CPU 预留峰值均为 917,504 字节，帧上传峰值均为 417,832 字节。

捕获／上传帧工作峰值分别为 104.436 ms 和 161.879 ms，主要来自首次小转向架捕获。后台简化已经拆出，但完整模型回调仍不可中断；当前不能声称首次捕获满足 2 ms 硬上限。后续要进一步降低该峰值，需要拆细捕获工作单元。

两条管线在同一路径均提交平均 87,960 个 LoD 三角形，完整模型为 663,296 个。Sodium 的专属场景 GPU 中位时间为完整模型 0.2990 ms／LoD 0.0225 ms，Iris 为 0.3297 ms／0.0297 ms；LoD 选择增加 CPU 提交时间。这些数值是既有完整模型／LoD 策略的当前对照，不是本轮异步改造的历史性能收益。Iris 日志保留光影包在 1.21.1 下未知 uniform 的 WARN，预期 Iris 管线及实际补丁着色器验证通过，无 ERROR／FATAL 或回退。

本轮证据目录为 `build/reports/third-batch-create/`，包括旧基准备份、失败 GPU 记录、最终构建／JUnit／GPU 汇总、Sodium／Iris 日志与报告及源码／产物校验清单。

标准 build 通过：279 项中 244 项通过，35 项 GPU 按默认配置跳过，失败为零。Mixin 检查通过 93 个注册、103 个目标与 281 项成员检查，10 个缺少可选依赖的目标明确跳过；中英各 232 个语言键及 137 个静态引用检查通过。

显式 GPU build 的 279 项全部通过，35 项 GPU 在 RTX 4060 Laptop／OpenGL 4.6 上实际执行，没有跳过。分发 JAR 已检查异步服务、主帧入口、关闭入口、分块上传与 CPU 释放的字节码，且不含模型基准／网络压力探针。归档 `voxy-0.2.19-beta+neoforge.jar` 的 SHA-256 为 `f80c9d2024f8c42ea6d8a812693bcf01a40f3bed56ab3122f38a51da3c737c2c`，完整汇总为 `verification.json`。
