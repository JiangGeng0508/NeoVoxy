# 客户端异步网络注入

本文记录 roadmap 第二批客户端后台消费、载荷合并、缺映射等待和队列背压阶段。该阶段使用 V1，区段线上格式、存储格式与默认画质没有变化。后续实现的可选 V2 视距协商及后台生成下游压力滞回见 [V2 视距与生成背压](network-view-backpressure.md)。

## 线程与顺序

`VoxyClientNetwork` 在客户端主线程检查载荷坐标、登记需求并取得目标世界；区段校验、调色板转换、32³ 体素解码、冷读取及写入由 `LodClientIngestion` 执行。映射页的 NBT 解码、映射导入和持久化也进入同一个消费者。新消费者在统一服务池中使用权重 2，始终只保留一个执行令牌；增加服务线程或借用帮助线程不会同时运行两个消费者。

区段任务绑定收到载荷时的实际 `WorldEngine`，不在后台读取当前 Minecraft 世界。每个区段最多有一个当前任务和一个后续载荷；排队中的重复数据合并为最新载荷，正在执行时到达的更新只保留一个最新后续任务。新载荷即使被容量拒绝也推进期望版本，旧结果不能清除它的重试需求。主线程尚未处理的旧完成确认也会被新载荷取代。

后台先完整校验并生成独立体素数组，再读取目标区段；最终写入在会话关闭和区段版本检查之后进行，保留覆盖范围、子区段掩码、光照、表面载体及原有保存／建面通知。关闭检查与写入共享提交门，冷读取不占用登记锁。任务从入队到执行结束或取消持有世界引用，等待映射的任务继续持有引用。

各世界使用独立映射命名空间。映射任务从上一个快照复制受影响的 ID 数组，其他数组只读共享；已发布数组不会再被修改。映射完成通知唤醒等待任务，不轮询缺失 ID。主线程按每 tick 1 ms 的预算发布不可变快照并处理成功、缺失及重试确认，时间预算在回调之间检查，不进行体素扫描。已完成任务在确认前仍计入条目上限；空载荷同样经过有序处理和完成确认。

## 预算与恢复

| 项目 | 默认限制 |
|---|---|
| 载荷、解码预留与映射数组合计 | 64 MiB |
| 排队、执行、等待和待确认任务合计 | 1024 项；执行中任务的后续载荷单独计数 |
| 为映射保留的登记空间 | 16 MiB、16 个任务位置；小预算测试按比例缩减 |
| 区段解码预留 | 每个非空载荷额外预留 512 KiB，覆盖最大调色板和体素数组 |
| 主线程完成确认 | 每 tick 1 ms，在单个回调结束后检查 |

映射预留计入编码输入及新数组空间，已准备／已发布表和待发布数组保守计费，共享引用可以重复计费。载荷预算不包含对象元数据、NBT 解压工作区、已写入的世界缓存、线程或 Netty 上游缓冲；条目上限单独约束队列元数据。已关闭世界的映射表会清理并归还预算。

登记达到容量时暂停新的拉取，现有后台任务和映射修复继续运行。超过 75% 水位暂停，低于 50% 恢复；不足以容纳下一个载荷的拒绝也触发暂停。映射保留空间防止队列全在等待 ID 时无法接收解锁所需的映射页。

收到的区段先登记为 held，包括没有在途拉取的权威广播。不能保留载荷时，保留区段 key 并按原有 5 秒延迟重新请求，绕过本地负缓存导致的需求遗漏。读取、解码或写入失败同样保留重试；成功或服务器确认缺失后才释放请求状态。缺映射或映射页拒绝会继续通过 hello 请求修复。

断线递增连接代次，关闭旧请求队列并停止消费者；消费者先禁止提交，等待正在执行的工作结束，再释放排队和等待任务的世界引用。旧完成确认不会进入新请求会话。配置导致实例重建时也先停止网络消费者，再关闭世界；同一连接尚未完成的 key 转回重试，重新同步新实例的映射。

## 验证

15 项新增 CPU 回归覆盖实际后台冷读取和写入、主线程延迟确认、排队及运行中更新合并、旧确认替换、容量拒绝后的广播重试、无轮询的映射等待、真实映射／逐体素转换、非法调色板、空结果条目限制、1 ms 确认预算、关闭等待、映射预算／死锁恢复、世界身份隔离及多工作线程下的串行消费。故障回归进一步验证冷读取异常释放并发等待者、同一个 key 可以重试，以及体素写入后的发布失败不能误确认，重试成功后覆盖范围正确落盘。`ActiveSectionTracker` 在加载异常时移除未发布占位、归还数组并通知等待者，避免后续读取永久等待。现有连接和请求回归继续覆盖握手修复、512 个在途窗口、缺失缓存、失败延迟、维度需求和旧存储工作线程。
