# 服务端异步网络准备

roadmap 第二批的服务端区段准备、快照共享与映射页缓存已实现。客户端后台注入的后续实现见 [客户端异步网络说明](client-network-ingestion.md)；可选 V2 视距协商和生成背压尚未实现。协议仍为 V1，存储格式及默认画质保持原样。

## 准备与发送

`VoxyServerInstance` 使用 `LodServerPreparation`，在统一服务池中以权重 2 执行冷读取、区段序列化和映射编码。服务器 tick 只请求准备、取得已准备结果、检查发送条件并发送载荷。不存在的区段由后台生成空载荷；读取异常移除本次准备并保留调度器需求，不伪装为空区段。

区段缓存键包含实际 `WorldEngine` 身份、维度与区段 key，条目携带内部递增版本。排队期间的重复需求和更新合并为一次准备；执行期间发生更新时，发布阶段拒绝旧结果，后续 tick 重试。dirty 回调先失效缓存，再发布原有更新通知，即使该次通知没有感兴趣的玩家也失效缓存。发送前再次校验快照归属与版本；实际发送成功后才完成更新票据。检查之后与发送同时发生的更新仍由原有票据版本检查保留，不能被旧确认清除。

序列化使用现有区段锁，线程本地原生缓冲立即复制到缓存拥有的堆数组，避免后续序列化覆盖已准备载荷。多个玩家取得同一个有效结果。准备未完成、快照失效或发送失败时，需求保留，并在本 tick 暂缓该 key，继续尝试其他需求。

映射缓存按世界、映射类别和起始游标共享。每页最多 128 项，优先控制在 64 KiB；单个较大方块映射可以单独成页，但必须容纳在每玩家 512 KiB 预算内。后台编码一次，网络 codec 复用编码字节，保持原有线上格式。映射仅追加，旧页保持有效，新 ID 从下一游标补发。调度器在发送区段前复查映射游标，准备未完成时不推进游标。

## 预算与生命周期

| 项目 | 上限及口径 |
|---|---|
| 准备载荷与任务预留 | 合计 32 MiB；区段按最大序列化长度 327696 字节预留，映射任务预留 1 MiB |
| 在途任务 | 64 项，包含排队和执行 |
| 总条目 | 1024 项，包含准备任务、非空／空区段及映射页 |
| 缓存驱逐 | LRU，仅驱逐已准备结果；不取消执行中的任务 |
| 发送总量 | 每 tick 全服最多 32 包／2 MiB，每玩家最多 8 包／512 KiB，包含握手和映射 |

载荷预算计入区段堆数组、映射编码字节和保留的映射数组／字符串内容，以及所有准备任务预留；不包含条目元数据、线程本地序列化工作区和现有 Netty 发送缓冲。总条目上限单独限制空载荷与缓存元数据规模。准备超过容量时拒绝本次登记，调度器保留需求重试。

每个准备任务从登记到发布、失败或取消持有世界引用。关闭先停止接收新任务，等待执行中的读取完成，释放未执行任务引用，再关闭世界与服务池。已准备结果只保留独立字节，不持有活动区段引用；世界重新创建后身份不同，不能误用旧结果。

`preparationStats()` 输出当前／峰值载荷预算、当前／峰值在途任务、缓存区段／映射页数，以及准备次数、缓存命中、过期结果、失败和容量拒绝次数。拒绝次数包含后续重试，不等于丢弃需求数。
