# 摄取快照、合并与生成背压

本阶段推进 roadmap 第三批的摄取来源队列：私有快照、按区段合并、同一区段串行写入、数组计账、可重试批次的准入控制，以及关闭完成通知。普通事件来源尚无可靠的全量重拉／持久化溢出机制，因此 64 MiB 是准入目标，不是整个摄取链路的硬内存上限。

## 快照和队列

摄取入口在调用线程复制方块调色板、群系调色板和光照。工作线程不再读取普通原版区段的可变调色板；非标准容器继续走其复制接口，非标准只读群系容器通过 64 个值构造私有容器。均匀数据保留零长度位存储，光照计账不调用会展开均匀层的 `getData()`。

普通地形通常不保留 `LevelChunk`；调色板含 Create Copycat／FramedBlocks 候选状态的区段仍为既有材料适配器保留区块，包括尚需走清理路径的未使用旧条目。Domum 方块实体引用和 LittleTiles 捕获结果沿用既有规则。因此这里的快照保证限于方块、群系与光照输入，不代表兼容方块实体或整个世界在同一时刻的不可变快照。

队列键包含 `WorldEngine` 身份及三维 Minecraft 区段坐标。同一键最多一个运行任务和一个最新待办；替换待办不会多发服务票据。旧版本完成所有体素和 mip 写入后才调度新版本，避免两个工作线程把同一区段写回成较旧状态。不同区段仍能并行处理，服务权重维持 4。“最新”指队列接受的提交顺序，不是跨来源的全局世界版本。

待办替换立即释放旧任务的世界引用。批次任务若被替换，会收到失败完成通知，使生成进度保持未完成、后续可重试；不会在尚未写入时报告成功。等待中的新任务不会修改正在运行的快照。

无区块更新通常依赖之前摄取保存的兼容材料。若旧输入尚在待办队列，合并会继承新输入缺少且新方块状态仍需要的 Domum／LittleTiles 数据或 Copycat／FramedBlocks 区块来源，并将继承后的估算纳入准入判断。新输入显式提供的数据优先；新状态已无相应持有方块时不继承旧数据。这个规则避免合并跳过了原本会先保存材料的旧任务。

继承标志检查实际使用的状态计数，不能只用 `maybeHas()`：删除方块后，调色板可能仍保留未使用的旧条目。此处防止整段已无相应类型时继承旧数据；兼容适配器内部的逐持有方块存储恢复规则沿用原实现。

## 计账和准入

| 项目 | 口径 |
|---|---|
| `arrayBytes` | 私有方块／群系位存储 `long[]` 和非均匀光照 `byte[]` 的实际长度 |
| `compatibilityBytes` | Domum 引用槽和 LittleTiles holders／材料／cell 的估算负载 |
| 字节目标 | 上述两项合计 64 MiB，含排队与执行中 |
| 任务目标 | 2000 项，含排队与执行中；同一键可以同时占两项 |
| `peakBytes` | 队列计账总量的历史最大值，含兼容估算 |

兼容估算按每引用槽 8 字节、每个 LittleTiles cell 对象加列表引用 40 字节、每个 material 对象加列表引用 32 字节，以及 holders 的实际 `long[]` 长度计算。它不是 JVM 对象布局测量。调色板实现内部对象／引用表、对象头、工作线程转换缓存、捕获期间临时分配、仍保留的兼容区块／实体对象图及其他缓存未计入。没有把此数值包装成进程堆占用或硬上限，也没有将本队列的 Java 数据算成原生／GPU 字节。

只有显式提供 `IngestBatch` 的可重试请求会因容量被拒绝；判断会扣除将被替换的待办，但不会扣除执行中任务。拒绝时原待办保持不变，不转移世界引用或批次完成责任，调用方继续按原约定执行一次 `batch.taskDone(false)`。`DistantWorldGenerator` 已采用此约定，并在整批实际成功后才标记完成。

普通区块加载、方块／光照更新、外部无批次注入等入口没有这样的重试保证，仍接受最新来源并合并同键待办。超过目标时累计 `overTarget`，不阻塞主线程，也不为满足数值上限丢弃更新。因此不同区段持续涌入仍可超过目标；完整硬预算需要下一阶段为这些来源补齐可恢复的溢出／重拉机制。

后台生成直接读取当前实例的摄取字节压力，与已有任务数、保存、网络和建面压力取最大值：超过 75% 暂停新生成，所有下游低于 50% 才恢复。已经生成的任务仍被收获。F3 分列排队／执行中／键数、数组字节／兼容估算／目标，以及合并、可重试拒绝和超目标次数。

## 完成和关闭

摄取引用从捕获前取得，拒绝或捕获异常时归还；已接受任务在转换结束、被替换或关闭取消时归还。所有被接受的批次任务恰好得到一次完成通知；返回 `false` 的请求仍由调用方报告失败。回调在队列锁外调用，避免回调重入时阻塞队列锁。

关闭先停止入队并取消待办，再等待正在运行的服务工作单元结束，禁止关闭后追加到已排空的队列。`blockTillEmpty()` 现在同时检查排队和执行中任务，以单调时钟处理超时，不会在最后一个任务刚被取走时提前报告排空。实例关闭仍先尝试完整排空，超时后的取消批次会明确失败。

## 验证

定向测试覆盖私有方块／群系／光照快照、均匀存储不展开、同世界同键合并与世界身份隔离、票据数、运行中内存计账、字节／条目容量、普通事件超目标保留、拒绝后的批次责任与重试、替换批次失败、最终体素写入、同一区段执行顺序、其他区段并行、转换失败、排空超时、待办取消、运行中关闭和世界引用释放。首次测试夹具使用了不存在的三参数 `WorldSection.get`，编译失败记录保留；修正为线性索引后定向回归通过。

实际 Sodium／Iris 模型夹具额外记录摄取计账峰值与合并次数，并检查字节非负、键与运行／待办数量一致。原五类区段几何比较、Create 异步准备和 960 帧／320 项准备样本继续执行。普通来源允许超目标，因此夹具不把超过 64 MiB 当作丢弃数据的理由。

证据归档：`build/reports/third-batch-ingest/`。完整兼容材料游戏验收、普通来源硬预算、其他节点请求／子区段更新队列，以及超大 Create 捕获拆分仍未完成。
