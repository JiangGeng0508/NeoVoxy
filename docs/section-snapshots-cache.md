# 区段快照与共享 secondary LRU

本轮实现 roadmap 第三批的区段私有快照和实例内缓存预算。默认画质、视距、体素编码及磁盘格式不变；来源与其他结果队列的字节背压仍是后续工作。

## 建面快照

每个 `RenderDataFactory` 持有可复用的 `SectionSnapshot`。在区段锁内复制体素和子区段标志，退出锁后运行连接纹理、季节替换、模型依赖检查及建面。均匀空气可以直接返回空结果；其他均匀区段只填充工作线程自己的 256 KiB 数组，不调用共享区段的 `materialize()`。下一次建面复用同一数组，模型等待任务不保留该数组或区段引用。

六个相邻面使用 `WorldSection.copyFaceInto()` 在各自区段锁内复制 1024 个体素，直接写入工作线程已有的邻面数组。面方向、布局、缺失邻段及顶面天空光行为保持原样。复制后立即释放邻段引用；不再使用分开的 `isUniform()`／数组读取，也不展开均匀邻段。

Create 连接纹理的 26 个邻段槽按需保存私有快照，复制后立即释放区段引用，同一视图中的重复读取不会看到后来写入的新值。快照槽与替换数组由对应建面上下文复用；均匀邻段只保存一个值，曾展开的槽可以复用自己的数组。最坏情况下 26 个稠密邻段槽占 6.5 MiB／工作上下文，中心快照和 CT 替换各另占 256 KiB。它们属于工作区，不计入 secondary LRU。

季节建面使用相同中心快照及私有邻面数组，上方区段改为一次复制底面。旧存档季节刷新也改为读取私有快照，并在写回时重新加区段锁、复查原方块 ID；父层写入在父区段锁内进行，通知在解锁后发布。这样不会让季节写入绕过快照保护，也避免覆盖摄取已经替换的方块。

这里保证的是每个区段相对于遵守区段锁的写入批次的一致性，不是多个区段在同一时刻的全世界快照。保存、摄取和 SeedGen 的现有直接写入接口继续使用；外部调用者仍须遵循引用与锁约定。

## 缓存预算与生命周期

每个 `VoxyInstance` 持有一个 `SecondarySectionCache`，所有维度／子世界共用同一 LRU。缓存键包含 tracker 身份和区段坐标，因此不同世界相同坐标互不覆盖。没有实例的独立 `WorldEngine` 使用自己的预算，便于工具及测试使用。

| 限制 | 默认值 |
|---|---|
| 体素数组字节 | `clamp(最大堆 / 16, 64 MiB, 256 MiB)` |
| 条目数 | 沿用原阈值：通常 1024，最大堆接近或超过 4 GiB 时 2048；现在由实例共享 |
| 均匀条目 | 0 字节体素数组，仍占一个条目 |
| 稠密条目 | 每个 `long[32768]` 为 262,144 字节 |

取出条目时扣除字节，再恢复活动引用；最后一个活动引用释放且保存完成后，才重新进入 LRU。加入后按全局最近使用顺序驱逐，直到条目数和字节都满足限制。单个条目装不下时直接归还数组，不清空其他可容纳条目。`DONT_CACHE` 继续绕过缓存。

活动、脏数据及保存中的区段不进入 LRU。`trySetFreed()` 在改变引用状态前先检查脏／保存标志。活动区段不会因缓存压力被硬驱逐，保存失败仍保持原有重试路径。锁顺序固定为 tracker 分片锁 → 共享缓存锁；缓存不会反向获取其他 tracker 的锁。世界关闭只清理自己的条目，归还数组并解除缓存对该世界的引用。

F3 的 `SCC instance` 行显示实例总条目、体素数组字节、两项上限和容量驱逐次数；原 ACC/SCC 行仍显示当前世界的活动／缓存条目。字节预算不包括对象头、覆盖标记、Mapper、工作快照、活动区段或静态数组复用池。驱逐的数组可能进入已有复用池，池继续受原配置约束；因此缓存变小不等于 JVM 已用堆立即减少。

## 验证与范围

定向 CPU 回归覆盖均匀区段不展开、稠密快照独立性与数组复用、六面坐标布局、锁内批次不被读到一半、连接纹理邻段版本稳定、共享缓存相同坐标隔离、全局 LRU 顺序、条目／字节限制、零预算、活动／脏／保存状态保护、DONT_CACHE、按世界清理，以及 4 个线程共 8000 次取得／释放与数组池复用竞争。保存回归另验证失败重试提交前不能进入 secondary cache。

模型基准增加真实游戏探针：空气、石头、玻璃、水和 Create 机壳分别使用均匀／展开存储构建，比较几何字节、offset、包围盒与子区段标志，并确认来源未被展开或替换。首轮因第一次邻段读取返回缺失、下一次返回缓存占位空气，两个输入环境不同而失败；固定并持有相同 26 个邻段后复测通过。保留该失败日志与 crash report。

Sodium 和 Iris 两条管线均通过五组快照比较，几何大小依次为 0、192、192、40,992、768 字节；随后原 Create 基准也完成共 960 帧、320 项准备耗时样本。这证明这些模型的两种存储形式等价，不是完整视觉验收或相对历史二进制的性能提升。Iris 使用实际 Complementary Reimagined r5.8.1；完整季节外观与 Vista／SeedGen 游戏组合仍需单独验收。

本轮证据归档于 `build/reports/third-batch-sections/`：定向回归、首次游戏失败、两个模型基准、双客户端压力、最终构建／JUnit／GPU 汇总及分发包／源码校验清单。

2026-11-01 的双客户端运行 `run-20261101-193637` 通过，总耗时 138.262 秒（含启动和退出）。Slow 使用 V1，Fast 使用 V2；两端各验证 2304 个最终金块区段、600 个唯一缺失请求和最终本地存储，队列排空，三个进程正常退出。Fast 有 57 次容量拒绝后成功恢复，处理失败为零；服务端更新队列峰值 2048、一次补发扫描后清空。这是生命周期与最终数据正确性验证，不是缓存性能对照。
