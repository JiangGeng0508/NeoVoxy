# 节点回读预算与子区段通知合并

本阶段推进 roadmap 第三批的节点输入队列。GPU 节点请求和几何清理回读在提交下载前预留容量；子区段存在性通知按监听位置合并，不再排队持有 `WorldSection`。画质、视距、存储格式及 GPU 请求格式不变。

## 回读容量与所有权

| 队列（每渲染器） | 字节预算 | 条目上限 |
|---|---:|---:|
| 节点请求回读 | 16 KiB | 64 |
| 几何清理回读 | 128 KiB | 64 |

预留覆盖等待 GPU 下载、已经复制的 CPU 原生缓冲，以及节点线程正在处理的批次。节点请求先按完整的 408 字节 GPU 请求缓冲预留，回调只复制有效请求并将预留缩减为实际大小；零请求立即释放。清理批次预留 2048 字节。取出批次不归还容量，完成处理或异常退出时才释放；每轮至多处理各 64 批。

请求预算不足时不下载，也不清零 GPU 请求缓冲。已有请求留在固定 50 项的 GPU 队列中；原有 shader 容量检查阻止越界追加，容量恢复后继续下载。清理则在 shader 修改可见性时间戳之前取得预留，失败时保持候选项可供下一轮处理。两条路径都不阻塞渲染线程等待消费者。

停止节点线程后，关闭队列释放尚未返回的预留和已复制缓冲；关闭后到达的下载回调不再复制。正在处理的批次由节点线程的 `finally` 释放。节点线程异常停止也允许执行资源清理，重复停止不会再次释放。

这里的 `nativeBytes` 是 CPU 独占拷贝的实际大小，`reservedBytes` 包含尚未发生的拷贝预留。共享的 32 MiB 持久映射下载流、GPU 请求／清理缓冲、队列对象头和引用槽另属既有基础设施，不重复计入。节点同步暂存与 GPU 几何仍单独报告。

## 子区段通知

注册子区段监听时登记位置，取消监听时删除。事件只更新已有记录中的最新 8 位存在性和待处理标志，不新增事件条目、不取得区段引用，也不读取体素数组。重复通知合并；在邮箱锁内读取当前存在性，避免延迟的旧回调覆盖新状态。

节点线程每轮最多扫描 4096 个哈希槽，取出最多 256 个位置和掩码，再在锁外调用节点管理器。输出数组复用，避免回调增删监听时死锁。扫描游标在扩容时重置，删除移位留下的待处理项通过回绕继续收获。取消监听会取消其未交付通知；关闭与生产者串行化，拒绝后续登记与更新。

计账报告邮箱实际 `long[]`／`short[]` 长度和固定 2304 字节输出数组，不包含对象头及原有路由监听表。邮箱条目数随有效子区段监听数增长；事件突发不会扩大数组。8192 个待处理位置是新生成的准入目标，既有监听超过它时仍保留每个位置的最新状态。这不是整个节点系统的固定堆上限：持久节点树、内部 single／child 请求、顶层增删集合及建面 key 仍遵循各自生命周期和既有容量约束。

F3 分列请求／清理的原生预留与实际字节、批次数、延后次数，以及子区段待处理／监听／合并数和堆数组大小。后台生成增加上述两项字节／条目压力及子区段待处理压力，沿用超过 75% 暂停、全部低于 50% 恢复；客户端按实例身份向集成服务器发布快照。

## 验证

定向回归 17 项通过，覆盖字节／条目独立容量、下载前预留、复制缩减、运行中所有权、回调失败和关闭取消、并发准入，以及零位置键、万次重复通知、1 万个不同监听位置、取消重登、回调重入、扩容／删除／扫描回绕和关闭竞争。

首次 Sodium 游戏启动遇到 1×1 窗口：旧 draw Hi-Z 的 mip 层数计算得到零，导致纹理分配失败和 framebuffer 不完整。修正为至少一层，保持其他尺寸的原有层数；新增 GPU 回归直接执行生产分配路径，验证 1×1、1×16、16×1 和 64×32 的纹理层数、尺寸、完整性及释放。失败日志和崩溃目录保留为 `sodium-failed-1x1.log`／`sodium-failed-1x1/`，修正后的 Sodium 游戏重跑通过。

干净 Iris 目录还暴露了夹具配置差异：历史目录的 `distant_gen_enabled` 为 false，新建目录此前没有显式配置，会采用生产默认 true。两次运行虽完成绘制采样，却在退出时停留于 `ChunkMap.processUnloads`／`CompletableFuture.postComplete`；线程快照中的 Voxy 工作线程和节点线程均空闲，最终人工终止测试进程，不能计为正常退出。另一次试验等待区块静止后关闭，但持续后台生成使等待超时，记录同样保留。最终夹具显式关闭后台生成，保持历史模型负载，正常调用客户端关闭；没有修改生产默认，也没有宣称后台生成退出问题已修复。

Sodium／Iris 模型夹具的逐 tick 预算、实际字节、条目数和子区段监听计账断言均通过；两条管线完成五类区段几何比较、共 960 帧及 320 项准备样本，并正常保存及退出。采样结果如下：

| 管线 | tick 样本 | 请求原生预留峰值（字节） | 子区段邮箱堆数组峰值（字节） | 待处理位置采样峰值 |
|---|---:|---:|---:|---:|
| Sodium | 231 | 856 | 40,970 | 2 |
| Iris + Complementary Reimagined r5.8.1 | 192 | 1,296 | 40,970 | 0 |

两边清理回读和容量拒绝的采样均为零；Iris 的零待处理采样也不代表没有瞬时通知。容量拒绝与恢复由定向回归覆盖，不能据此声称这些路径已通过实机压力验收。完整构建、GPU 和游戏运行结果归档于 `build/reports/third-batch-node-queues/`。

V1／V2 双客户端运行 `run-20261107-144106` 通过，用时 138.25 秒（含启动退出）。两端各完成 2304 个最终区段、600 个唯一缺失请求、本地存储复查和队列排空，三进程正常退出；Slow 的 10 次载荷容量拒绝后恢复，两端处理失败为零。这验证网络回归，不是节点清理吞吐或后台生成退出验收。
