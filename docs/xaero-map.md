# Xaero World Map 地表兼容

NeoVoxy 可以用已有 LOD 补全 Xaero 世界地图。适配版本为 **Minecraft 1.21.1 / NeoForge、Xaero World Map 1.47.0**；Xaero Minimap 26.4.2 的世界地图模式读取同一份地图。没有安装 World Map 时不启用兼容层，其他 World Map 版本会记录明确日志并关闭同步。Xaero 依赖仅用于编译，不随 NeoVoxy 打包。

## 使用

在 Sodium 的 NeoVoxy 设置中打开“Xaero 世界地图”页。默认启用同步与粗 LOD，正常使用、导入或收到 LOD 后会在后台逐步补全地图，不需要玩家先走到该区域。旧缓存只在正常读取或已经驻留内存时进入任务，不枚举整个 LOD 数据库。

| 设置 | JSON 字段 | 默认 / 范围 | 作用 |
|---|---|---|---|
| 同步 LOD 地表 | `xaero_map_sync` | `true` | 总开关；关闭会取消待处理任务，已保存地图仍可读取 |
| 使用近似 LOD | `xaero_map_coarse` | `true` | 允许 LOD1～4；关闭后只从 LOD0 提取 |
| 每秒瓦片数 | `xaero_map_tiles_per_second` | `20` / 1～128 | 后台每秒最多提取的 16×16 地图瓦片 |
| 提交预算 | `xaero_map_commit_millis` | `2` / 1～10 ms | 每个客户端 tick 的软预算，最多提交四个瓦片 |
| 待处理区域上限 | `xaero_map_queue_regions` | `256` / 16～4096 | 每个区域覆盖 512×512 格；仅配置文件提供 |

配置文件是 `config/voxy-config.json`。NeoForge 的 `config/voxy-client.toml` 使用对应驼峰字段，例如 `xaeroMapSync`。沿用仓库的配置同步方式：初次加载以 JSON 为准，设置页保存同步到 TOML；TOML 重载会同步回客户端配置。区域队列上限在下一次会话绑定时生效，其他设置在 tick 中生效。

提交预算不是硬实时上限；64×64 着色更新由 Xaero 的原生纹理上传流程执行，同一纹理的多个瓦片写入可以合并。后台线程只短暂持有单个 WorldSection，提交队列仅保存最多八个已提取瓦片。队列按水平区域和区域内部游标轮转，持续更新低坐标不会饿死后面的瓦片。等待加载、缓存或 PBO 的区域退回坐标队列，延迟 250 ms 后重新提取最新数据，其余区域可以继续提交。超限会淘汰最久未处理的区域；该区域下次有 LOD 可用/变化通知时重试。断开日志给出完成、实际更改、未更改、延后次数和区域淘汰量。大批量导入超过队列容量时，部分区域需后续正常加载才能补全，可提前调高区域上限；不通过扫描整个数据库补偿。

### 生成完成与地图刷新时间

LOD 生成、地图地表提取、Xaero 纹理上传和磁盘缓存是不同阶段。默认 20 瓦片/秒意味着一个 512×512 区域的 1024 个瓦片单遍至少约 51 秒；128 区块半径的圆形范围约 5.1 万个瓦片，单遍约 43 分钟。两种生成可以并行，因此这不是生成结束后必然还要等的时间；重复通知、缺数据的尝试、加载等待与帧率也影响实际耗时。希望更快补图时可把“每秒瓦片数”提高到 64；它会增加后台提取负担，客户端每 tick 仍最多提交四个瓦片。

内置种子地形预览已移除；种子生成需使用外部 SeedGen。普通后台生成的区块仍会进入地图同步队列。Xaero 单人模式从 MCA 构建地图时还会等待集成服务器保存，之后有原生上传、缓存和保存开销。兼容层的增量写入只更新受影响的纹理，不再为邻居请求整区域刷新；完全相同的像素不重绘，只有来源精度提升时保存标记。正常的缓存加载动画仍可能短暂出现。

## 地表与来源规则

- 支持有天空光、无顶棚的普通地表维度；Xaero 高度编码范围限制为 `[-2048, 2048)`。
- LOD0 每格采样，LOD1～4 分别扩展为 2、4、8、16 格近似采样。精细结果优先；粗数据不能降级更精细结果。
- 缺失 section 和旧格式的空气不表示已知天空。已提供的非空气是证据；只有覆盖记录确认的空气才能擦除较粗地形。垂直上方有未知数据时，结果标记为暂定，可由后续完整数据修正。同精度的暂定结果不能降级已确认结果。
- 使用 Xaero 的不可见方块、透明度及着色规则；保留地面、水面高度、生物群系、方块光和基本透明覆盖层。旧 LOD 缺少覆盖记录时仍可显示暂定地表，不能据此证明整列已探明。
- 真实区块扫描的地图优先。未知空白、LOD 来源、LOD 精度及暂定状态随像素一起保存；重新启动后仍按这些规则处理。真实扫描即使与 LOD 像素相同，也会移除 LOD 所有权。
- 基本水面、水含方块和透明覆盖受支持；LOD 本身丢失的细节无法恢复。覆盖层最多保留十种连续材料，重复材料累积透明度。

洞穴分层、下界特殊选层、独立小地图扫描不在支持范围。此功能不额外请求服务器 LOD、不生成精细 LOD、不新增服务端地表摘要协议。Minimap 必须开启它自己的世界地图模式，才能复用结果。

## 存储与线程契约

`WorldEngine` 提供独立的数据可用通知，不替换渲染 dirty 回调。新生成和世界导入通过 `WorldUpdater`，网络注入通过原来的 dirty 路径，磁盘/LRU 成功读取通过 `ActiveSectionTracker` 通知。生产线程只交付坐标键；单独后台线程按一个水平瓦片和维度高度读取本地数据，之后提交到客户端线程。

覆盖记录使用 Voxy section 现有头部的备用五个字节（标识 `VOXY` 与八个 octant 位），包长和存储版本不变。LOD0 的原版 16³ section 对应一个 octant；粗层只有在该 octant 的全部子 section 都被提供后才确认。未完成的粗层计数仅驻留内存，淘汰后重新累计，避免把缺失数据判为空气。

Xaero 提交使用 `renderThreadPauseSync → writerThreadPauseSync → MapRegion` 的锁顺序，明确请求源像素并等待原生加载状态 2；已有纹理缓存不能代替来源检查。未加载的池化瓦片中残留的旧像素不视为当前位置的真实地图。不同时锁住两个地图区域。使用 `MapTileChunk.setTile/setToUpdateBuffers`，由 `LeafRegionTexture.preUpload` 调用原生 `updateBuffers`，保留原生加载、缓存及保存流程；区域处理列表避免重复注册。切换世界、维度、Xaero 子世界或退出时解绑监听器、取消 worker 并丢弃旧结果。手动换子世界不会重放上一个绑定的驻留 LOD，且需在 Xaero 中确认子世界可写后才绑定。

多人游戏/普通 Xaero 地图直接保存到 Xaero 的区域 ZIP。单人默认使用 MCA 地图，Xaero 通常不会保存源像素；因此把 LOD 补充保存在 Xaero 对应世界、维度目录下的 `voxy-surface/<regionX>_<regionZ>.zip`，仍使用 Xaero 的原生 ZIP 编码、临时文件替换和保存线程。读入时先读取 MCA，再补充其未覆盖像素，不写 Minecraft MCA 文件。启动区域发现会枚举这些 Xaero 补充文件。

内部接口严格对应 World Map 1.47.0 / 源格式 6.8：像素头部空闲位 29～31 保存来源（0=真实/外部、1～5=LOD0～4、6=未知填充），位 7 保存暂定状态。位 2～5 为 LOD 像素补足 `topHeight` 的高四位，解决原生不同顶面高度只保存低八位的问题。能力检查或处理异常会停止同步并记录日志；补充文件读写失败不会传播为整个客户端的异常。升级 Xaero 前需要重新核对这些内部契约，不能仅放宽版本门槛。

卸载兼容层后，普通原生地图仍能被 Xaero 读取，但单人 MCA 模式不再发现 `voxy-surface` 补充文件；地图的来源规则也依赖此兼容层。没有另建需要与区域文件配对提交的来源索引。

## 验证

本机实际验收结果及其边界见 [2026-10-22 验收记录](xaero-validation-2026-10-22.md)与 [2026-10-29 补图与刷新排查](xaero-validation-2026-10-29.md)。

CPU 回归覆盖未知天空、已知空气、负坐标、跨 section/地图区域边界、维度高度裁剪、水面/透明覆盖、生物群系、粗细替换、覆盖头部往返及旧格式、四类通知涉及的公共入口、持续更新时的队列公平性、繁忙区域延后重试，以及十万区域通知的队列上限。运行仓库标准 `build`，见 [自动验证说明](testing.md)。

真实客户端验证脚本与方法见 [隔离游戏验收](../scripts/xaero-smoke/README.md)。它使用新建测试世界、实际 Xaero 加载/保存和两个独立 JVM 验证重启持久化，同时检查导入、接收、来源、瓦片卸载后再更新、相同像素的真实扫描接管、子世界原生 ZIP 重载与维度切换。网络接收验收调用实际客户端 payload handler，但没有启动远端专用服务器或经过网络 socket。最小客户端组合包含 Sodium、World Map 1.47.0 和可选 Minimap 26.4.2；不等同于整个整合包的长期多人性能验收。
